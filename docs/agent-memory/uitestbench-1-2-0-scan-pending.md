1.2.0 的「屏幕取景框扫码」已随 1.3.0 一起发布，代码与设计理由在 `docs/architecture.md` 与源码注释里；这里只留仓库不易看出的部分：

- 取景框是 **368×452 玻璃卡片**，中央 320×320 完全镂空，毛玻璃只铺四条边框；捕获区只取中间 320×320，不是整个面板。
- 面板出现后有 **2 秒准备期**：捕获照常启动（预热），`ScanSession.startAt` 之前不判定；之后光带扫、识别开始。命中后停扫、对勾 1 秒、恢复主窗口，主窗口的「下载」只是确认下载。
- 对勾图标在 flipped layer 里曾上下倒置：`NSImage(flipped: false)` 是 y 向上坐标，拐点必须比两端低。
- AVIF 保留：较新 macOS 的 ImageIO 能解码，移除是回退；12.3 打不开会落到中文提示。

实扫进展：2026-10-23 用户已在应用里扫过开发提供的真实二维码（那次正是「链接其实是 APK 下载页」bug 的来源），识别 → 面板 → 下载这一段已走通；1.4.2 已补上 JS 空壳下载页的详情接口。**未做**（只能由用户本人验）：玻璃卡片/2 秒准备期/光带/对勾的观感；Retina 与 12.3 上的毛玻璃与圆角；飞书/微信/浏览器各种来源、小码、暗色、视频中的码；多显示器/全屏/Space；ad-hoc 重签后的授权错位；以及用 1.4.2 复测完整扫码下载链路。

**Why:** 「已实现/已打包」不等于「已验证」；剩余的是真实环境观感与兼容性。

**How to apply:** 汇报扫码状态时明确上述手工验收未做，不要声称已验收。相关：[[uitestbench-1-4-release-pending]]、[[uitestbench-plan-location]]。
